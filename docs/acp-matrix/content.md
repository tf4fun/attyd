# ACP 内容、通知与控件源码清单

[总矩阵与版本基线](../acp-bridge-matrix.md) · [源码闭合索引](schema-index.md)


审计对象是 **ACP → bridge 权威内存**，不是 FE，也不是已完成实现声明。所有本地项目路径默认指 experiment `991b053`；`main:` 指稳定 v1 rc.5 `60f8606`（功能同 `488ccd9`，只升级 rustls）。本轮只写审查文档，未运行行为测试。

当前 Rust SDK `754d5aa` / schema **1.7.0**；项目启用 `unstable`，但它不含 `unstable_protocol_v2`。Zed固定 `9f63850` 使用 SDK **3.4.0** / schema **1.12.0**，只能作为实现比较，不能直接作为当前规范。

本章负责全部 `content.rs`、`tool_call.rs`、`plan.rs`，以及通知/controls/结果相关 client.rs、agent.rs 类型。其余 RPC、初始化、session lifecycle、交互、FS/terminal 服务和公共类型由其他分册闭合。

机械闭合：79 个 struct/enum（全 schema 277 个中的本分册集合），183 个命名字段、72 个 enum variants；32 条语义矩阵行，补齐 enum 行后 84 条；18 条独立于 FE 的验收约束。[source-inventory.json](source-inventory.json) 收录全部类型字段、cfg/serde 属性、行号和上游声明对照；原始注释和定义以固定源码链接为准。

## 使用边界

- schema事实、SDK解析边界、bridge展示内存策略、Zed实现分别列出，不互相冒充。
- 本分册所称保留是所属bridge内存文档仍存在时保留当前可展示语义，不要求无限事件日志、磁盘持久化或ACP server未提供的历史。
- Option<T>通常使null/缺省成为None；MaybeUndefined保留三态。VecSkipError/DefaultOnError导致的typed ingress损失不能归因于后续canon；raw wire之外的未知字段保真不是当前schema保证。
- 完成turn可压缩分片/通知为语义状态，但不可把已显示tool/thought/plan/compaction结果直接丢弃；覆盖/移除后释放无引用资源。
- FE不参与本阶段oracle，检查脚本Agent源事实与bridge权威内存；Zed不是协议规范。

`_meta` 包络缺口不等于必须保存每次通知：可以保留与可展示语义关联的元数据；具体表达仍需确定。字段源码若为 `Option`，不要把原始 JSON 中 `null` 的测试误当三态支持。

## 现有实现差异归类

- 已证实 v1 回退：完成/普通失败后工具、thought 等已接收内容被丢；idle/late 更新不入稳定显示内存；消息 ID/chunk 元数据与内容 `_meta` 在 canon 消失；controls update 根 `_meta` 与 response modes 根 `_meta` 被简化掉；已嵌入终端释放后的快照能力退化。
- 两边共同限制：通知封套 `_meta` 未保留；permission-only tool 未形成独立 retained 内容；完整失败 outcome 未形成长期记录；v1 也不保证跨连接持久化；跨 turn plan 等实体归约并非全部正确；rc.5 compaction.summary 附件遍历有遗漏。
- 尚需明确的归约政策：ToolCallUpdate `_meta`、UsageUpdate 无 cost 的 last-known 表示、response usage 计量文字歧义、通知封套 provenance。先忠实保存已解析事实，不新增无限历史日志或供应商特殊规则。
- 诊断/导出/UI折叠不是本章的强制恢复范围。已有 r2 文档是否覆盖某项，必须区别“已规定、待实施”与“规范仍缺”：本章不把迁移未完成本身判为新设计缺陷。

## 模型选择与仍待明确的边界

- 通知封套_meta已确认两边都丢；目标需决定如何把相关provenance放入显示状态，不能据此强制持久化所有通知/无限eventlog。
- ToolCallUpdate._meta：r2 §3.2 已选择按 Option 字段归约，提供值时替换，缺省/null 保持；SDK helper 仅更新 fields、不触 meta，不能把 bridge 的选择写成 SDK 原生保证。
- UsageUpdate.cost：r2 §4.5 已选择缺省/null 保留最后已知 cost；这是 bridge 的显示状态政策。PromptResponse.usage 的源注释仍有 turn/session 计量歧义，保存收到的值，不自行推导累计或增量。
- 1.7 CompactionUpdate允许same-ID后续patch的文字，与现semantic.rs拒绝任何终态后update是否冲突，需专门typed测试/协议依据；新版1.12明显放宽，不能混用。
- ResourceLink.size i64与bridge非负/JS-safe校验、Location.line索引基础等，不在schema未明文处追加“ACP规范”要求。
- PromptResponse.usage 的计数是 schema u64；两条基线相同的 `semantic.rs:154–177,841–851` 却限制 JS safe integer，并检查单项/输入输出和不超过 total。将这些实现限制和数值边界列入 EN-01/A17 的直接验收，不能仅凭 schema 字段存在就称完整值域支持。UsageUpdate.used/size 的校验是另一条路径（`:598–606`），不要误套这个 safe-integer 限制。
