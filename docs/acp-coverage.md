# ACP v1 client coverage

This matrix is the acceptance ledger for `attyd` as an ACP client. Production uses protocol version `1` through the official Rust SDK (schema `1.7.0`, Rust SDK git revision pinned in `Cargo.lock`); the TypeScript SDK `1.4.0` supplies independent test peers. “Supported” means the bridge, browser state, UI, and tests implement the negotiated behavior; merely having an SDK type does not count. The stable-v1 SDK entry points also expose explicitly unstable extensions, including fork, ACP-transport MCP, ID-addressed plans, prompt usage, compaction, provider configuration, and NES. Those surfaces remain labeled experimental or as an explicit product exclusion below.

`attyd` deliberately has no application access authentication, users, tenants, provider registry, session database, or persistent completed-history store. Agent account authentication remains Agent-owned: attyd invokes only methods advertised through ACP. Agent-handled methods never expose credential fields to attyd; terminal methods run the Agent's own interactive login program in a bounded PTY with ephemeral browser scrollback and no durable input log. Agent-owned session persistence is accessed only through ACP lifecycle methods. The bridge retains an in-memory baseline plus one active turn per materialized session; [active-turn-runtime.md](active-turn-runtime.md) defines the recovery contract and no-load degradation.

## Compatibility contract

The [ACP v1 specification](https://agentclientprotocol.com/protocol/v1/transports)
and negotiated capabilities define compatibility. Tests exercise protocol requests,
responses, notifications, cancellation, and lifecycle behavior through SDK fixtures.
A particular Agent's behavior does not override that contract.

Stdio, HTTP/SSE, and WebSocket are implemented. Stdio is the specified baseline;
the current ACP transport document lists Streamable HTTP as a draft and permits
custom transports. The remote modes use the SDK transport profile and preserve ACP
JSON-RPC semantics. Experimental methods remain capability-gated and identified below.

## Cross-cutting invariants

- Optional methods are rejected server-side unless the Agent advertised the matching capability.
- Agent authentication is separate from attyd access control. Method IDs, names, descriptions, counts, Agent-provided terminal argv/environment, terminal input/output, and relay payloads are bounded; duplicate IDs are rejected. No credential field exists in the browser UI. Agent-handled authentication, terminal authentication, and logout are serialized; acknowledgement events commit only to the exact pending request, and stale successes remain isolated diagnostics. In stdio mode, terminal auth never invokes `authenticate`: it reproduces the configured Agent command without a shell, appends only the advertised args, applies environment overrides server-side, and uses a real PTY/xterm interaction. Remote transports omit the terminal-auth capability and reject a nonconforming Agent that advertises such a method anyway. A successful zero exit triggers browser reconnect because ACP requires a fresh initialized Agent; nonzero exit and cancellation remain retryable. After `logout`, the existing session remains visible because ACP does not define its fate; the Client waits for actual Agent errors rather than deleting it optimistically.
- Prompt, cancel, filesystem, terminal, permission, elicitation, mode, and config operations are rejected for unknown sessions; mode/config values must have been offered by the Agent.
- Conversation updates for unknown, inactive or idle sessions are dropped like Zed's missing-thread path, preventing a close/load race or physically late update from surfacing in an unrelated turn. Active updates are folded only into the session's one active turn. A valid cold-load candidate atomically installs the shared baseline; every completed prompt and observed overlay then atomically extends that process-local baseline without another load.
- Load replay is one validation and delivery transaction: every replayed update uses the same bounded payload checks as an active session, while dynamic mode notifications remain Agent-owned and the later response establishes final mode/config controls. A structurally invalid, oversized, interrupted or rejected replay aborts the replacement without exposing partial history; if the ACP request cannot be cancelled, the bridge drains and discards it before accepting another operation.
- Sessions are keyed by `sessionId`; the bridge retains a shared in-memory baseline, an optional active turn, bounded idempotency/control metadata and live resources. Conversation bytes are accounted but do not have a bridge-defined cumulative admission cap. Refresh and browser replacement read that same bridge projection without triggering load. A terminal turn committed with no session subscriber is followed by capability-gated `session/close` and projection release; its next observer cold-loads from the Agent. If close is unavailable or fails, the projection remains in memory. A new no-load session remains reconstructable only until bridge exit. Different session IDs may have concurrent prompts, while prompt/load/mutation exclusion remains per session.
- While a browser transaction is pending, lifecycle and control acknowledgements commit only when request ID, operation kind, and target session all match; mismatches remain isolated diagnostics, including two successful `session/new` responses arriving in reverse order. If the originating browser has disconnected and no conflicting local transaction exists, the Bridge-owned lifecycle/mode/config event is accepted as runtime authority so a replacement browser can reconstruct the result.
- A conforming Agent may emit updates for a new or forked session before returning its session ID. While a creation request is pending, attyd validates and buffers at most 10,000 such updates/1 MB across candidate IDs, binds only the replay matching the returned ID, and commits it with the matching browser transaction. Invalid replays fail the creation and are discarded before a clean retry; response mode/config state remains authoritative because it occurs later on the ACP wire.
- When `session/new` or `session/fork` returns an unusable response after allocating a distinct session, attyd sends a best-effort `session/close` only if close was advertised, exactly one creation is pending, the ID is browser-addressable, and it cannot name a tracked, attaching, or deleting session. Duplicate new IDs and a fork that reuses its source ID are deliberately never auto-closed, preventing cleanup from terminating valid user state.
- A failed `session/load` or `session/resume` validation similarly closes only its exact, still-exclusive pending attachment when close was advertised. It never closes a session that reached tracked state or entered deletion.
- Prompt completion and prompt errors likewise settle only the exact pending request in its current or cached session. A rejected rapid duplicate cannot unlock the original turn, and a stale same-session completion cannot append a stop card or re-enable the composer. Bridge stop/error phases abandon pending prompts; closing a browser SSE subscription does not cancel an active prompt.
- Prompt responses are bounded before reaching the browser. Per-turn token counts must be non-negative safe integers, individual counts cannot exceed `totalTokens`, and input plus output cannot exceed the reported total. Valid usage is rendered semantically beside the exact ACP stop reason while the original response remains inspectable.
- Session `usage_update` remains distinct from ambiguous prompt-response token accounting: its Agent-reported context window and optional cumulative cost are rendered beside the composer as a Zed-style usage ring. The disclosure shows exact used, size, remaining, and currency values; warning color starts at 80%, while no compaction or summary capability is inferred from usage alone.
- A pending fork preserves the source timeline but disables UI mutation. The bridge rejects duplicate forks and source-session prompt, close, mode, or configuration changes until the fork settles; stale or mismatched fork responses cannot commit in the reducer.
- A pending close likewise preserves visible context while disabling mutation. Duplicate close and concurrent prompt, fork, mode, or configuration operations are rejected; failure releases the lock and restores the session, while only the matching success clears it.
- Mode and configuration changes share one per-session transaction. While one is pending, the bridge rejects another control change plus prompt, fork, and close; the UI also disables these mutations. Agent failure releases the lock without optimistic state changes, and only the matching response may commit the requested control.
- A pending deletion disables attachment and duplicate deletion for its target; an attachment already in flight also blocks deletion. Failures release the target without removing it from the UI, and only a matching success removes the listed session.
- Malformed browser messages and oversized command types, request/session IDs, cursors, paths, URIs, and control IDs produce compact request errors without reaching the Agent or poisoning the ACP connection.
- Browser-bound server events pass a runtime envelope/discriminant check before entering React state. Browser command send failures are surfaced in the visible timeline and do not trigger optimistic state changes. The Rust host owns no completed session-event journal: it keeps one folded active turn, live-resource state, typed delivery queues, small control metadata and a shared in-memory baseline only. A subscriber receives an atomic baseline-plus-active snapshot and suffix. Returning from background keeps a healthy stream and performs a bounded bridge probe; a stale mobile connection reconnects without cancelling an active turn. `visibilitychange`, `pageshow`, `pagehide`, `online`, and focus are all covered. Terminal connection states also cover the disabled composer with a user-invoked reconnect action.
- Home, project, and session pages use the full width without a sidebar or a separate global toolbar. Navigation, titles, and actions share the page content column. Home offers New project, which takes a working directory and starts its first session; project pages create sessions within that project. An independent back link always goes to the structural parent, including for shared URLs. Idle browser-cache membership is not displayed as a session status. The session title dropdown filters and switches within the project; Agent settings sit alongside the page actions. Both menus fit desktop/mobile viewports, dismiss on outside clicks or Escape, and restore trigger focus on Escape. Permission and elicitation cards likewise focus their first action, map Escape to ACP `cancelled`/`cancel`, lock every action while a response is pending, retain local failures for retry, and unwind focus correctly even when multiple Agent interactions are stacked. The Agent composer mirrors Zed's `Shift+Alt+Escape` expanded message-composer interaction while preserving the exact draft, attachments, completion menus, and negotiated session controls; this is not a file-editor surface. A pending permission, form, or external flow deterministically returns it to auto-height so the ACP interaction cannot be obscured. When the draft is empty, ↑/↓ traverses a session-bound, 100-entry history derived from local and Agent-replayed user messages. Recalled image, audio, resource, resource-link, annotations, and block ordering are resent exactly unless the user edits the recalled draft; adjacent identical local/protocol echoes are collapsed without collapsing intentional repeated prompts across turns. These behaviors and slash-command keyboard submission have portable DOM interaction tests.
- Agent-thread search is a presentation-only index over visible semantic conversation content. `Ctrl/⌘F` opens a Zed-style search bar with case, whole-word, regex, wrapping navigation, count, and highlight state; Escape closes it and restores composer focus. Collapsed thought/tool bodies are indexed only after expansion, raw ACP inspectors never contribute duplicate hits, and streamed updates are rescanned after 150 ms. Queries are capped at 256 characters, scans at 2,000,000 characters, and retained matches at 10,000; invalid patterns remain a local UI error and never create ACP traffic.
- Production-browser CI drives a fresh real Rust host and stdio SDK Agent through the browser REST/SSE API per Chromium case. It verifies permission subject disclosure (tool name, location, and raw input), permission and full form elicitation focus entry/restoration, Agent-handled and real-PTY terminal authentication/reconnect, active-turn survival and restoration across browser replacement, two concurrent session turns with local switching and busy-session deletion guards, explicit composer recovery after an Agent exit, queued follow-ups plus Stop/pause/new-message resume and `session/cancel` Send now/FIFO dispatch, clipboard-image, dropped resource, and `@`-selected workspace context reaching the Agent in order, complete attachment-prompt ↑/↓ recall, live thought auto-expansion followed by tool-phase collapse and manual reinspection, default-collapsed terminal output entering search only after expansion, bounded read-only Agent diff review without invented editor actions, structured ACP error inspection plus exact failed-ContentBlock retry, absence of an NES/editor entry point, mouse and Shift+F10 Agent-response context actions with focus restoration and complete Markdown export, semantic thread search with visibility rules/match navigation/highlighting, live `usage_update` context/cost disclosure beside the composer, desktop/mobile expanded message-composer bounds plus automatic return for a pending permission, successful browser-to-Agent responses, deterministic top/bottom long-thread navigation, desktop/mobile top-menu dismissal and focus restoration, absence of console/page errors, and desktop/mobile horizontal layout bounds; failure traces, screenshots, and the HTML report are retained as CI artifacts. The non-browser black-box suite drives the same production backend.
- Follow-up prompts are retained only for the current Agent session, capped at eight full capability-gated ACP prompts, cleared on session replacement or terminal bridge state, and emitted strictly after the preceding prompt settles. Queue editing never creates a protocol update; the user message enters the ACP timeline only after `session/prompt` is successfully written.
- Permission requests are self-contained tool upserts, so their carried patch may introduce or update the tool. Tool-scoped elicitations preserve the Agent's association without requiring a preceding visible tool update. Permission option collections and IDs remain bounded and unique.
- Session-scoped elicitations are isolated from the visible session; request-scoped elicitations survive session transitions. Their scope preserves string, safe-integer, and `null` JSON-RPC IDs, including an empty string, instead of treating valid but discouraged IDs as missing. Browser turn cancellation and Agent `$/cancel_request` both settle pending permission/elicitation RPCs exactly once and remove their UI cards.
- Agent `$/cancel_request` propagates into cancellable filesystem reads, pre-mutation filesystem writes, terminal `wait_for_exit`, and MCP connect/message handlers. Cancelled terminal waiters are removed immediately without killing or releasing the underlying process, so repeated cancellation cannot consume the per-terminal waiter budget and a later wait/kill/release lifecycle remains valid. A cancelled in-flight MCP connection attempt terminates its unannounced provider process before any connection ID can escape.
- Form elicitation schemas are bounded and checked before rendering; required fields, safe patterns, formats, enum fallbacks, unique multi-select values, numeric/length bounds, and defaults against their own constraints are revalidated server-side. Unknown elicitation modes and non-HTTP(S) URL handoffs are rejected.
- URL elicitation IDs cannot be reused within a connection. Completion notifications are relayed only for a tracked flow whose opening was accepted; accepted flows survive session switches and browser reconnects until completion, dismissal, explicit cancellation, or Bridge shutdown. Invalid or duplicate lifecycle events are dropped without poisoning the ACP connection.
- Cancelling or closing an ACP session aborts only accepted URL flows scoped to that session and emits an explicit bridge event so the UI cannot remain indefinitely in a waiting state. Request-scoped flows are not tied to that session and remain active. Completed and cancelled flows are terminal against late contradictory events.
- Recoverable command and Agent-update errors remain visible without falsely ending an active prompt. Only the matching prompt completion/failure or a stopped/error Bridge phase ends the Bridge-owned turn. A browser disconnect affects only that browser's disposable projection; reconnect reconstructs the still-running turn from the shared baseline and active overlay.
- Startup, subprocess, and ACP transport failures are reported to the browser before bridge resources close. A stopped/error phase transactionally rolls back any pending session switch and clears prompt/control/delete locks, pending interactions, MCP connections, and live terminal presentation so the UI cannot remain falsely actionable or permanently busy.
- ACP JSON-RPC `RequestError` codes and bounded error data are preserved in browser-visible errors; oversized Agent error details are truncated before reaching the browser API.
- Browser JSON request bodies are capped at 5 MiB, allowing the 3 MiB decoded attachment budget plus base64 and JSON overhead. Every complete Agent response or notification value that will be relayed is limited to 4,000,000 bytes including outer `_meta` and is checked before tracked state changes; stricter prompt, list, elicitation, MCP, terminal, and early-replay budgets still apply. Prompt attachments have a 3 MiB raw-byte limit, and Agent stdout NDJSON lines are rejected above 8 MB before SDK parsing.
- Binary content blocks are limited to 3 MiB decoded data and require canonical base64. MIME types, absolute resource URIs, linked-resource sizes, finite annotation priorities, and bounded annotation timestamps are validated for prompts plus Agent message, tool, and compaction output; invalid Agent updates are dropped without poisoning the connection. Protocol-defined annotations plus resource descriptions/MIME/sizes are visible, only HTTP(S) resource links become clickable, and invalid media degrades to a non-rendering status card.
- Picker, drag-and-drop, and clipboard attachments share one reservation-aware 3 MiB prompt budget, so concurrent browser file reads cannot over-commit the limit. Files are converted only to capability-offered image/audio/resource blocks; unsupported drops and pastes remain local visible errors and never reach the Agent. Unnamed clipboard media receives a stable synthetic attachment URI.
- `@` context search is available only when the Agent advertises `promptCapabilities.embeddedContext`. It scans at most 50,000 entries across the configured realpath-confined workspace roots, skips symlinks plus common dependency/generated directories, returns at most 24 text-file matches, and rechecks type, real path, and the shared 3 MiB prompt budget when the user selects a result. The exact UTF-8 file content and canonical `file:` URI are sent as an ACP embedded resource; stale search responses cannot replace newer results.
- Tracked sessions, listed session IDs and cursor history, pending creations/attachments/interactions, external flows, session controls, message/tool/plan/session-update collections, compactions, terminal create bytes/commands/arguments/environment, terminal count, output retention, and waiter count are bounded per Agent connection. Reused pagination cursors are rejected; repeated session IDs are safe client-side upserts rather than fatal protocol errors.
- `session/list` pages are limited to 4 MB and the retained pagination result to 16 MB/10,000 unique sessions. Rows use bounded portable absolute paths (POSIX, drive-letter, or UNC), contain at most 256 additional roots, and preserve bounded metadata even when `updatedAt` is not parseable. Workspace grouping uses the exact Agent-reported cwd; rows with missing or invalid dates follow dated rows within their workspace and retain the Agent's order.
- Terminal presentation snapshots are isolated to the visible session, coalesced to roughly 30 Hz, capped at 64 retained browser entries, and limited to 2 MB of cumulative non-terminal snapshot output per terminal. Exit and release snapshots bypass that live-update budget so the final bounded state is still visible; before release, a terminal-backed tool also retains the bounded final output, exit status and truncation flag in its in-memory `rawOutput`.
- Terminal creation is acknowledged only after the child emits `spawn`; a missing executable cannot escape a terminal ID or snapshot and leaves the manager reusable. The [terminal request](https://agentclientprotocol.com/protocol/v1/terminals) keeps the executable and arguments separate. attyd preserves both and never guesses a shell after a failed launch; shell execution requires an explicit shell command and arguments. OS exit values outside ACP's uint32/null domain are normalized to `null` before browser relay.
- ACP-transport MCP providers are declared by unique server IDs. Launch commands and environment variables remain host-private; only `{type, name, serverId}` reaches the Agent and only `{type, name}` reaches the browser metadata.
- ACP-transport MCP processes and pending requests are bounded per browser/Agent connection. Unknown and cross-connection IDs, invalid or contradictory responses, duplicate response IDs, oversized messages, ordered provider-start cancellation, message cancellation, disconnect, and named/status-bearing process exit are handled without reusing a connection. The pending-request reservation and close transition are atomic, so concurrent requests cannot cross the 128-request bound or insert work after termination.
- The stable-v1 initialization advertises only Agent-interaction capabilities. NES/document capability fields are absent, so conforming Agents cannot treat attyd as an editor host; unnegotiated editor methods are not exposed through the browser API.
- Agent JSON-RPC errors retain the safe-integer code and up to 256 KiB of structured `data` as separate fields. Larger `data` is explicitly marked as truncated with its original byte count instead of silently entering browser state. A matching failed prompt keeps the exact original ACP `ContentBlock[]` for Retry or Edit Prompt; stale and non-prompt failures cannot acquire retry state.
- ACP method, `SessionUpdate`, and content-block unions have typed coverage ledgers; newly added SDK variants fail compilation until classified and handled.
- Original ACP values remain available through raw inspectors; `_meta` values are not interpreted, but they count toward the same relay and retention budgets as protocol-defined fields. The server and browser reducers use exhaustive discriminant checks so new SDK union variants fail compilation until classified.

## Remaining verification work

- Keep the Rust backend coverage gate at or above 85% while expanding behavior. Native tests plus the real-binary UI and remote-transport harnesses cover semantic validation, configuration, filesystem/context, terminal/auth-terminal, capability/cwd, relay limits, early/late routing, cyclic pagination, session mutation, cancellable filesystem RPC, ordered MCP provider-start and message cancellation, disconnect/process-exit/128-pending-request recovery, oversized Agent lines, malformed protocol values, and post-failure liveness. The randomized cross-session reducer corpus correctly stays in the TypeScript frontend and is not a backend gap.
- Keep conformance fixtures aligned with the official ACP specification and negotiated capability combinations, including Agents that omit optional methods. Backend-specific smoke tests are optional diagnostics and do not define compatibility or justify protocol rewrites.
- Broaden the rendering-engine matrix beyond Chromium if cross-browser CSS or accessibility differences become a supported compatibility target; current CI uses production Chromium while portable DOM tests cover the wider interaction state space.
- Broaden deterministic adversarial generation as experimental ACP surfaces evolve; the current corpus exercises 5,000 arbitrary TypeScript parser values and 2,500 shuffled/cross-session updates per run, alongside native Rust validation and real HTTP boundary checks.
- NES and editor-document capabilities should stay unadvertised unless the product scope explicitly expands beyond the Agent interaction UI.
