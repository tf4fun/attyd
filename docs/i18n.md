# Interface translations

attyd uses [i18next](https://www.i18next.com/) with
[react-i18next](https://react.i18next.com/latest/usetranslation-hook) and
`i18next-browser-languagedetector`. English and Simplified Chinese are bundled
with the web interface, so language switching needs no translation service or
additional network request.

The default **Follow browser** option detects browser language preferences and
falls back to English. **Agent settings → Language** selects an explicit language.
Only that preference is saved in browser storage under `attyd.language`; detection
itself is not saved. Following the browser again removes the preference. If storage
is unavailable, switching still works in memory for the current page. Session
history remains subject to the existing in-memory design.

## Add a language

1. Copy `web/src/i18n/locales/en/` into a new BCP 47 language directory, such as `fr/`.
2. Translate the four JSON namespaces: `app`, `workspace`, `conversation`, and `cards`.
   Keep semantic keys unchanged. Preserve `{{variables}}`, formatting options,
   markup placeholders, and protocol names inside examples.
3. Import the files and register the language in `resources` in
   `web/src/i18n/index.ts`. Add its native name to `languageNames`; the selector
   reads this registry automatically.
4. Run `npm run check` and `npm run test:browser`. Review project, session, input,
   permission, and tool views at desktop and mobile widths with the new language.

Use i18next's [plural forms](https://www.i18next.com/translation-function/plurals)
for the target language (`_one`, `_other`, and other required categories) and pass
`count`. Translate complete phrases instead of assembling translated fragments.
The resource tests compare message coverage and interpolation variables across
languages while permitting different plural categories.

## Add or change a message

Components import `useTranslation` from the shared `web/src/i18n` entry point,
which initializes bundled resources before rendering:

```tsx
const { t } = useTranslation("workspace");
```

Add a semantic key to the appropriate namespace in every language, then call
`t` with interpolation values. English resources provide TypeScript key checking
and runtime fallback. Translate accessible labels, tooltips, validation messages,
and empty states alongside visible button text. Use the current resolved language
for `Intl` date/number formatting. Include `t` or the language in memo dependencies
when the memo contains translated output; keep connection and process lifecycle
effects independent of language.

## Translation boundary

Translate attyd's interface, not Agent replies, user prompts, paths, tool output,
Agent-provided configuration labels, or raw ACP fields. Original diagnostic errors
and historical events keep their recorded text; changing interface language does
not rewrite them. Structured form and attachment validation messages update when
the language changes. Known attyd history notices are translated at display time
by `history-notice.ts`; unknown notices pass through unchanged.

Tests cover browser detection, manual override, English fallback, storage failures,
plural rules, resource coverage, and preservation of drafts and Agent content.
Browser regressions also check that switching languages does not reload a session.
